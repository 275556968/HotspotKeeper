# HotspotKeeper

> 让你的 Windows 电脑像 iPhone / iPad 一样：**手机热点一出现，自动发现、自动连上**，不用再去开关一次热点。

---

## 一、它解决什么问题

**你的痛点**

- iPhone 之间 / iPad / Mac：手机热点一开，其他设备自己就发现并连上了；
- 你的 Windows 笔记本：热点开着、信号满格，可它就是**不自动连**，必须把热点关掉再打开，Windows 才会连上。

**为什么会这样**

你的热点配置文件里其实已经是「自动连接」了（我用 `netsh wlan show profile` 确认过）。问题出在 Windows 的
`WLAN AutoConfig` 服务上：

1. 它扫描得很"懒"——默认几十秒才扫一次，而且是在后台低优先级地扫；
2. 一旦某个网络**连续几次连不上**（握手失败、热点刚好在切换信道、刚从睡眠里恢复……），
   Windows 会把它打入"冷宫"，**不再主动重试**，界面上的表现就是"要手动关开一次热点"——
   其实是你手动操作时顺带触发了一次新的扫描和连接尝试；
3. 它不会为了某一个特定的 SSID 去做"定向探测"。

而 iOS 设备的行为是：**主动、频繁地向已知的热点发探测请求**，同时一有机会就发起连接。

HotspotKeeper 就是把这个行为搬到 Windows 上，直接调用系统原生的 `wlanapi.dll`：

| | iOS 设备 | Windows 默认 | HotspotKeeper |
|---|---|---|---|
| 扫描频率 | 高，后台持续 | 低，几十秒一次 | 可配，默认 **5 秒** |
| 定向探测特定 SSID | 会 | 不会 | **会**（关键） |
| 连不上之后 | 继续重试 | 放弃 | **退避重试**，冷却后继续 |
| 发现热点后 | 主动发起连接 | 等系统自己决定 | **立即 `WlanConnect`** |

## 二、快速开始

### 方式 A：一键安装（推荐）

在项目目录里打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -StartNow
```

安装脚本会：

1. 自动编译（使用 Windows 自带的 `csc.exe`，**不需要装 .NET SDK / Visual Studio**）；
2. 复制程序到 `%LOCALAPPDATA%\Programs\HotspotKeeper`（不需要管理员权限）；
3. 生成配置文件 `%LOCALAPPDATA%\HotspotKeeper\config.ini`，**自动识别出你手机热点的名字**；
4. 设置开机自启（写 `HKCU\...\Run`，只影响当前用户）；
5. 检查并修复热点配置的「自动连接」开关；
6. 立即启动，右下角托盘出现图标。

指定热点名字（默认会自动识别带 `iPhone` / `热点` 字样的网络）：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Targets "我的手机热点" -StartNow
```

### 方式 B：手动编译

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

产物在 `dist\`：

| 文件 | 用途 |
|---|---|
| `HotspotKeeper.exe` | 托盘版，双击即用（日常使用） |
| `HotspotKeeper-cli.exe` | 命令行版，看诊断 / 实时日志 |

然后双击 `dist\HotspotKeeper.exe` 即可。配置文件会在首次运行时自动生成。

## 四、配置项详解

配置文件：`%LOCALAPPDATA%\HotspotKeeper\config.ini`
（改完保存 → 托盘右键「重新加载配置」，或者等它 20 秒内自己生效）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `Targets` | 自动识别 | **要自动连接的热点名（SSID）**，多个用 `\|` 分隔，靠前的优先 |
| `ConnectWhen` | `nointernet` | 连接时机，见下节 |
| `ScanIntervalSeconds` | `5` | 没连上时的扫描间隔。越小发现越快、越费电，建议 3–10 |
| `IdleScanIntervalSeconds` | `3` | 已达成目标后的**状态巡检**间隔。只查询连接状态、不做射频扫描，几乎不耗资源；**设大了会导致掉线后要等很久才发现**，建议 2–5 |
| `ConnectTimeoutSeconds` | `15` | 发起连接后等多久算失败 |
| `MaxAttemptsBeforeCooldown` | `6` | 连续失败几次进入冷却 |
| `CooldownSeconds` | `90` | 冷却时长，冷却结束后继续尝试 |
| `MinSignalQuality` | `0` | 信号低于此值（0–100）就不连 |
| `DirectedScan` | `true` | **定向扫描**：主动向目标 SSID 发探测请求。这是提速的关键，建议保持 `true` |
| `BlindConnect` | `true` | **盲连**（最强的一招）：扫描列表里根本没有目标热点时，也直接按配置文件发起连接，等于主动去敲门而不是干等广播 |
| `BlindConnectIntervalSeconds` | `20` | 盲连间隔。太小会一直占着网卡，建议 15–30 |
| `SetNonBroadcast` | `true` | 把目标标成「非广播网络」，让 Windows 自己也持续向该 SSID 发定向探测 |
| `AutoFixProfile` | `true` | 启动时把目标热点配置的连接模式改回「自动连接」 |
| `SetAutoSwitch` | `false` | 是否连「即使已连其他网络也切过去」一起打开 |
| `NoInternetGraceSeconds` | `20` | `nointernet` 模式下，确认断网多久才切换（防抖动） |
| `WarmUpSeconds` | `3` | 程序启动后延迟多久开始工作 |
| `NotifyOnConnect` | `true` | 连上热点时弹提示气泡 |
| `Password` | 空 | 该热点从没在这台电脑上连过时，填密码让程序自动创建配置 |
| `AuthType` | `auto` | 创建配置时的加密方式：`auto` / `wpa2` / `wpa3` / `open` |
| `InterfaceName` | 空 | 多网卡时指定无线网卡（名称关键字） |
| `StartWithWindows` | `auto` | `auto`=不改动；`true`/`false`=强制开关 |
| `LogLevel` | `info` | `debug` / `info` / `warn` / `error` |
| `LogRetentionDays` | `7` | 日志保留天数 |

### 连接时机（`ConnectWhen`）三种模式

| 值 | 行为 | 适用场景 |
|---|---|---|
| `disconnected` | **只有完全没连任何 Wi-Fi 时**才去连热点 | 最保守，绝不打扰你现有的网络 |
| `nointernet` | 没连 Wi-Fi，**或者连着的 Wi-Fi 上不了网**（持续 20 秒）时去连热点 | **默认，最接近 iOS 的体验** |
| `always` | 只要热点在范围内就切过去 | 想让热点优先于一切（比如宿舍宽带很慢） |

> `nointernet` 的"能不能上网"是用 TCP 直连公共 DNS 的 53 端口来判断的（不依赖 DNS 解析，比 ping 可靠）。
> 如果你插着网线且有网，它不会去抢热点。

## 五、命令行工具

两个 exe 都能用这些参数（`--diagnose` 等会自动把输出接回你运行它的那个终端）：

```powershell
# 无线环境全量诊断：网卡 / 当前连接 / 所有配置文件及其连接模式 / 可见网络 / 联网探测
HotspotKeeper-cli.exe --diagnose

# 只扫描一次
HotspotKeeper-cli.exe --scan

# 只尝试连接一次，并报告用了多久连上
HotspotKeeper-cli.exe --connect

# 前台运行，实时输出状态（排查问题最好用）
HotspotKeeper-cli.exe --console

# 列出所有已保存的无线配置及其 connectionMode
HotspotKeeper-cli.exe --list-profiles

# 把目标热点的配置改回「自动连接」
HotspotKeeper-cli.exe --fix-profile

# 热点空闲行为诊断：断开后观察热点多久消失、消失后能否被"叫醒"
# （期间会断网，默认 180 秒，结束自动连回；结果写进日志）
HotspotKeeper-cli.exe --probe-idle 240

# 使用指定的配置文件
HotspotKeeper-cli.exe --console --config D:\my.ini
```

退出码：`0` 成功 / `3` 没发现目标 / `4` 目标没有已保存的配置 / `5` 连接超时。

## 六、常见问题

**Q：装了之后还是连不上？**

按顺序排查：

1. `HotspotKeeper-cli.exe --console`，看它是不是每 5 秒在"定向扫描"；
2. 手机热点开着的时候，`HotspotKeeper-cli.exe --scan`，看列表里**有没有**你的热点名字：
   - **有** → 程序应该会在几秒内连上；如果提示"没有已保存的连接配置"，说明这台电脑从没连过该热点，
     先手动连一次，或者在配置里填 `Password = 你的热点密码`；
   - **没有** → 是手机没在广播（见下一条），不是电脑的问题；
3. 看日志：`%LOCALAPPDATA%\HotspotKeeper\logs\`。

**Q：iPhone 热点明明开着，扫描列表里却没有？**

先说实测结论（在你自己的机器上跑出来的，见第九节）：

> **断开电脑 Wi-Fi 后连续 240 秒、92 次探测，`MyHotspot` 一直可见，一次都没消失。**
> 也就是说——至少在这 4 分钟里，你的手机**根本没有停止广播**。

所以"手机一开热点就停播"这个说法在你的场景里是不成立的，真正不干活的是 Windows。
换成手机长时间锁屏、深度睡眠、或者被带走之后再回来，才可能出现热点真的消失的情况。
程序现在会把「热点从列表消失 → 多久后重新出现」写进日志，用一两天就能拿到你手机的真实数据。

如果你确实遇到了"扫不到"：

1. 先跑 `--probe-idle 240`，让程序自己告诉你热点是"停播了"还是"一直可见"；
2. 若结论是"停播且叫不醒"，那就是手机的省电策略，任何 Windows 软件都无法唤醒它（见下一条）；
3. 若结论是"一直可见"，那说明是扫描/连接的问题，跑 `--diagnose` 把结果发我。

**Q：如果确诊是"手机真的停播、且叫不醒"，还有救吗？**

那种情况下 Windows 侧**没有任何办法**（射频都关了，物理上不存在的东西扫不到）。可行的路只有三条：

| 办法 | 说明 | 代价 |
|---|---|---|
| **USB 线共享网络** | 插上数据线，iPhone 会自动开 USB 网络共享，完全不依赖 Wi-Fi 广播；而且手机热点处于"在用"状态，Wi-Fi 也就不容易休眠 | 要一根线 |
| **留一台常连设备** | 旧手机 / iPad / ESP32 插着电、一直连着热点，热点就永远不会进入空闲休眠，SSID 也就一直在 | 要一台闲置设备 |
| **iPhone 打开「最大兼容性」** | 强制 2.4GHz，部分机型上热点更"黏"、更不容易休眠 | 只有 2.4GHz，速度上限低 |

本程序已经把这些尽量绕开了：**盲连**会每 20 秒主动敲门，万一热点只是"不出声"而不是"关机"，立刻就能连上。

**Q：会不会很费电 / 很占资源？**

程序常驻内存约 30 MB，CPU 占用基本为 0（每 5 秒一次本地 API 调用，没有轮询界面）。
连上热点后会自动降到 20 秒一次的巡检。笔记本出门在外如果不想让它扫，托盘点「暂停监控」即可。

**Q：会不会抢我的网？**

默认 `ConnectWhen = nointernet`：只有**没网**的时候才会去连热点。你在家连着路由器、插着网线都不受影响。

**Q：能同时配多个热点吗？**

可以，`Targets = 家里的热点|公司的热点|备用热点`，按顺序找，谁先出现连谁。

**Q：卸载**

```powershell
powershell -ExecutionPolicy Bypass -File .\uninstall.ps1              # 保留配置和日志
powershell -ExecutionPolicy Bypass -File .\uninstall.ps1 -PurgeConfig # 全删
```

卸载只清理程序本体、开机自启和（可选的）配置日志，**不会动 Windows 里已保存的无线网络**。

## 八、技术细节

- **编译**：`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（系统自带，C# 5），
  零第三方依赖，产物约 55 KB。注意源码是 UTF-8，编译脚本里必须带 `/codepage:65001`，
  否则中文字符串会变乱码。
- **P/Invoke 要点**：所有含 `WCHAR[256]` 的互操作结构体必须标注
  `[StructLayout(LayoutKind.Sequential, CharSet = CharSet.Unicode)]`，
  否则默认按 ANSI 编组，结构体尺寸会少 256 字节（`WLAN_INTERFACE_INFO` 会变成 276 而不是 532），
  读出来的 SSID 和网卡名全是乱码。程序里的 `--diagnose` 会自检这几个尺寸。
- **定向扫描**：`WlanScan(hClient, &guid, &dot11Ssid, NULL, NULL)` 传入目标 SSID 即为定向扫描，
  只针对该 SSID 发探测请求，比全信道扫描更快也更省电。
- **主动连接**：`WlanConnect` 使用 `wlan_connection_mode_profile` 模式，按配置文件连接，
  不需要管理员权限。

## 十、真正的根因：iPhone 会关掉热点射频（以及在手机上的解药）

### 实测证据（2026-10-17 12:11–12:25，本机日志原文）

| 时间 | 事件 | 说明 |
|---|---|---|
| 12:11:27 | 已连上 `MyHotspot` | 正常使用 |
| 12:13:55 | 已离开目标热点（信号 15%） | 手机被带走，开始远离 |
| 12:13–12:15 | 6 次发起连接，全部失败 | 还能看到它，但太远，连不上 |
| **12:17:10** | **`MyHotspot` 从扫描列表消失** | 手机把热点**射频关了** |
| 12:17–12:25 | **23 次盲连，全部失败** | 定向探测也敲不开——它真的关机了 |
| 12:25:13 | 已连上（4 秒） | 用户关开一次热点，程序立刻抓住 |

**结论：手机在没有设备连接约 3 分钟后会关闭热点射频。**
射频关掉之后，Scan 扫不到、定向探测没有回应、`WlanConnect` 也连不上——
**这不是 Windows 的问题，也不是任何 PC 软件能解决的**（物理上不存在的东西扫不到）。

> 注意：程序本身是有效的。12:25 你手动关开热点后，它 **4 秒**就连上了；
> 而且在 12:13–12:15 那 6 次尝试里，只要距离够近就能连上。

### 解药：让 iPhone 自己把热点打开（一次性设置，永久生效）

iOS 快捷指令里有 **「设定个人热点」** 这个动作，可以自动化开关热点。
配一个「蓝牙」触发器，因为你这台电脑和 iPhone 已经配对过、蓝牙一直连着
（设备名 `MY-LAPTOP`，iPhone 侧显示为 `MyHotspot`，当前 HFP/A2DP 都处于 OK 状态）。

**第 1 个自动化：回来就开热点**

1. iPhone 打开「快捷指令」→ 底部「自动化」→ 右上角「+」
2. 选「蓝牙」→ 设备选 **`MY-LAPTOP`**（你这台电脑）→ 条件选「**已连接**」→ 下一步
3. 选「新建空白自动化」→ 搜索框输入「热点」→ 选「**设定个人热点**」→ 打开
4. 关掉「运行前询问」，选「立即运行」

**第 2 个自动化：走就关热点（省电）**

同样步骤，但第 2 步条件选「**已断开**」，第 3 步把「设定个人热点」设为 **关闭**。

这样：手机回到电脑旁 → 蓝牙自动重连 → 热点自动打开 → **本程序 2~4 秒内连上**。

### 其他可选解法

| 方案 | 适用 | 说明 |
|---|---|---|
| USB 线网络共享 | 桌面固定使用 | 不依赖 Wi-Fi 广播，插上就有网；iOS 会自动开 USB 共享 |
| 换 Android 手机开热点 | 长期需求 | Android 热点不会因空闲自动关闭，从根上没这个问题 |
| 回到 3 分钟内 | 短时间离开 | 实测约 3 分钟以内回来，热点还活着，本程序能自动连回 |
